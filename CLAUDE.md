# CLAUDE.md — рабочие заметки по репозиторию

## План

`PLAN.md` — архитектура и вехи M0…M8, все пройдены. Решения, принятые с
пользователем, зафиксированы там же в шапке; расхождения плана и того, что
получилось, отмечены в конце.

## Команды

```bash
npm run check     # tsc + eslint (запрещает `as`-касты) + vitest
npm run smoke     # браузерный смоук; --preview для прод-сборки
npm run build     # прод-сборка → ./docs (GitHub Pages)
```

Golden-тесты пиннят геометрию семейств; пересоздавать осознанно:
`UPDATE_GOLDEN=1 npx vitest run tests/golden.test.ts`.

## Инструменты: постоянные скрипты вместо одноразовых

Не писать временные Playwright/Node-скрипты через `cat > tmp.mjs <<EOF` —
это выброшенные токены на каждом цикле. Многоразовая обвязка живёт в
`scripts/lib/harness.mjs`; новые проверки добавлять **флагом к существующему
скрипту**, а не клонировать его.

- `scripts/smoke.mjs` — браузерный смоук: все семейства, пресеты, формы
  волны, узоры накатки, крайние положения ползунков, ссылка, отмена/повтор,
  оснастка и реальная выгрузка STL. Флаги: `--preview`, `--shots <dir>`.
- `scripts/snap.mjs` — точечный скриншот в заданном состоянии. Флаги:
  `--out` (обязателен), `--family`, `--set <id>=<value>`, `--check <id>`,
  `--uncheck <id>`, `--click <selector>`, `--view` (только канвас),
  `--wait <ms>`, `--width/--height`, `--preview`.
- `scripts/lib/harness.mjs` — разбор флагов, поднятие vite (перед `--preview`
  сам пересобирает), сбор ошибок консоли.

## Архитектурные инварианты

- `src/geo/` — чистое ядро геометрии, **никогда** не импортирует Three.js.
- Ядро считает **в миллиметрах** (в отличие от mathsculpt с относительными
  единицами): у посуды реальные размеры — часть смысла. `encodeSTL` поэтому
  по умолчанию `scale = 1`.
- Ось модели — z, дно изделия в z = 0. Рендер сам поворачивает в y-up.
- Плоскость разъёма формы — XZ (y = 0). Ручка и носик обязаны лежать в ней:
  ручка при x < 0, носик при x > 0.
- Всё, что приходит извне (UI, ссылки, localStorage), проходит
  `sanitizeState`. Санаторы не бросают ни на чём и идемпотентны — это
  проверяется тестами.
- CSG (`src/geo/csg.ts`) — WASM manifold-3d. Объекты Manifold не собираются
  GC: всё, что создано, держать в `CsgScope` и звать `dispose()`.

## Что сколько стоит

Замерено на M1 Mac, сетка 192×192 (74 тыс. треугольников):

| Операция | Время |
|---|---|
| сборка изделия (параметрическая) | 10 мс |
| полное `validateMesh` | 60 мс |
| CSG: полое изделие + ручка | 320 мс |
| оснастка (блоки или ванночки) | сотни мс |

Отсюда раскладка в `main.ts`: изделие пересобирается на каждое движение
ползунка, проверка меша откладывается на 220 мс, оснастка — на 400 мс и
считается на огрублённой сетке. Ручка в превью рисуется отдельным мешем:
непрозрачные пересекающиеся тела выглядят ровно как их объединение, а
настоящий union нужен только в STL.

## Чего в v1 нет

- Приставного трубчатого носика (есть только оттянутый край).
- Скруглённых наружных рёбер гипсового блока.
- Веб-воркера: узкое место — CSG, а не резолюция, и оно решается задержкой.
