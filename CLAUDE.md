# CLAUDE.md — рабочие заметки по репозиторию

## Оснастка — в cast-builder

Литейную оснастку (мастер, ванночки под силикон, отминочную форму с
пуансоном) строит отдельное приложение
[cast-builder](https://github.com/dmitryweiner/cast-builder)
(`~/projects/cast-builder`) по готовому STL. Clayform отдаёт ему ровно то,
что печатают глиной: полое изделие, крышку юбкой вниз. Сплошной мастер
cast-builder заливает сам — через горловину и канал носика, крышку — после
переворота юбкой вверх; два предмета в одном файле («Крышка рядом») он
отвергает. Своего сплошного экспорта у clayform больше нет
(`plans/PLAN-EXPORT.md`). Под кнопкой экспорта — ссылка на него. Тесты
cast-builder стоят на STL, выгруженных ядром clayform (`fixtures/README.md`
там; печатные пересобирает его `scripts/fixtures.mjs` из исходников clayform).
После правок тела, носика, крышки или дна — проверка, что каждый
встроенный пресет, выгруженный печатным, cast-builder заливает в мастер
(~25 с): `cd ../cast-builder && node scripts/fixtures.mjs --presets`
(`--res <n>`, по умолчанию 192; `--concave` — то же с вогнутым дном обоих
видов и сверкой глубины пола отминочной формы, ~50 с). Скрипт сам грузит
TypeScript clayform и кита через module runner Vite, `vite-node` не нужен.

## maker-kit — общие куски 3D-инструментов

Панель и её строки, отмена, хранилище, пресеты, файл проекта, лист на
телефоне, диалог, баннер, полоса прогресса, список сообщений и список полос,
выбор языка, очередь воркера, меши, STL, сито экспорта, мост к manifold,
3D-вид, обвязка смоука, шрифты (`ui/fonts`), растр текста
(`ui/textRaster`), импорт картинки (`ui/imageImport`), контуры растра
(`core/raster`), поле высот (`3d/heightfield`) и дизайн-код — китовые
([maker-kit](https://github.com/dmitryweiner/maker-kit),
`~/projects/maker-kit`, по тегу: `#v0.6.0`). Своё у clayform — геометрия
посуды (`src/geo/`), карточки, выбор семейства силуэтами, график профиля,
строка картинки с ✕ (`ui/controls.ts` рисует её между строками кита),
раскладка надписей по стенке (`geo/decal.ts`) и их тела (`geo/decalSolid.ts`),
свесы для печати (`geo/overhang.ts`), терракота и ракурсы
вида (`render/scene.ts`), своя тёплая палитра токенами поверх китовых.

Правило (`~/projects/_conventions/3d-tools.md`): своей копии китового куска
нет. Ошибка или недостающий случай в ките — PR в кит с тестом, патч-тег,
затем clayform переезжает на тег; совместная работа — `npm link
../maker-kit`. Опция в кит — только когда она нужна двум приложениям, иначе
приложение оборачивает кусок кита. Документация кита — в его `docs/`
(пакет её не везёт), витрина — <https://dmitryweiner.github.io/maker-kit/>.

## Деплой

GitHub Pages публикует `.github/workflows/deploy.yml` на каждый пуш в
`main`: `npm ci`, `npm run check`, `npm run build`, проверка, что в главном
чанке нет `manifold`, смоук на прод-сборке (`npm run smoke -- --preview`) и
выкладка `dist/`. На PR — всё то же без выкладки. Сборка в репозиторий больше не
коммитится (`dist/` в `.gitignore`); Node — из `.node-version`.

## Офлайн (PWA)

Приложение — PWA (`_conventions/pwa.md`, куски шаблона): `src/sw-plugin.ts`
пишет `dist/sw.js`, который кладёт в кэш сборку и `public/` (CSG-воркер,
его `.wasm`, шрифты клейма), кэш зовётся `clayform-<hash>`; `skipWaiting` и
`clients.claim`. `src/pwa.ts` регистрирует его только в сборке, просит
обновление при каждом возвращении на страницу и перезагружает её на
`controllerchange` — изделие хранится при каждой правке, теряется только
история отмены. `public/manifest.webmanifest`; `public/icon.svg` —
единственный источник иконок (`npm run icons` рисует PNG). Смоук с
`--preview` проверяет офлайн (страница, воркер и WASM из кэша, выгрузка
STL без сети) и то, что новый `sw.js` перезагружает открытую страницу.

## Команды

```bash
npm run check     # tsc (TypeScript 7) + oxlint --type-aware (запрещает `as`-касты) + prettier --check + vitest
npm run format    # prettier --write (кроме *.md и golden: .prettierignore)
npm run smoke     # браузерный смоук (dev :5281); --preview — прод-сборка (:4281)
npm run build     # прод-сборка → ./dist; на Pages публикует GH Actions
```

Линтер — oxlint (`.oxlintrc.json`): typescript-eslint TS 7 не понимает.
`as`-касты запрещает `typescript/consistent-type-assertions`, `as const`
можно; каждое выключенное там правило подписано, почему. Форматирует
prettier; коммит переформатирования — в `.git-blame-ignore-revs`
(`git config blame.ignoreRevsFile .git-blame-ignore-revs`). Сетки меандра
стоят под `// prettier-ignore`: строки сетки и есть рисунок.

Golden-тесты пиннят геометрию семейств; пересоздавать осознанно:
`UPDATE_GOLDEN=1 npx vitest run tests/golden.test.ts`.

## Инструменты: постоянные скрипты вместо одноразовых

Не писать временные Playwright/Node-скрипты через `cat > tmp.mjs <<EOF` —
это выброшенные токены на каждом цикле. Многоразовая обвязка живёт в
`scripts/lib/harness.mjs`; новые проверки добавлять **флагом к существующему
скрипту**, а не клонировать его.

- `scripts/smoke.mjs` — браузерный смоук: все семейства, пресеты, формы
  и готовые узоры волны, узоры накатки, оба вида носика, крайние положения
  ползунков, старая ссылка `#s=` (открывает изделие из браузера),
  отмена/повтор, точная сборка изделия, полоса прогресса и реальная
  выгрузка STL, файл пресета, мобильная панель, клеймо с подблоком лого,
  текст и картинка на боку (на всех семействах, через шов, вердикт точной
  сборки — `settledVerdict`), вогнутое дно, язык
  (переключение, память выбора, чистый en-US). Браузер открывается в
  `ru-RU`: проверки читают русский текст. Флаги:
  `--preview`, `--shots <dir>`, `--res <n>` (детализация экспорта),
  `--slow` (CDP `setCPUThrottlingRate(6)` на шагах полосы прогресса;
  замедляет только главный поток — воркер считает как есть). Время
  каждой выгрузки печатается всегда — им и меряется стоимость экспорта.
- `scripts/snap.mjs` — точечный скриншот в заданном состоянии. Печатает
  заодно статус, вердикт проверки меша и предупреждения. Флаги: `--out`
  (обязателен), `--family`, `--preset <id>` (`teapot`, `amphora`…),
  `--lang ru|en` (по умолчанию ru), `--set <id>=<value>`,
  `--check <id>`, `--uncheck <id>`, `--click <selector>`,
  `--upload <id>=<path>` (файл в `<input type=file>`; действия идут в
  порядке командной строки), `--view` (только
  канвас), `--clip x,y,w,h` (кусок кадра — разглядеть стык вблизи),
  `--orbit dx,dy` (повернуть камеру мышью — заглянуть внутрь изделия),
  `--url <path>` (статический ассет), `--wait <ms>`, `--width/--height`,
  `--preview`.

  Точную сборку изделия видно не сразу: она подъезжает примерно через
  секунду после последней правки, поэтому для неё нужен `--wait 3000`.
- `scripts/icons.mjs` — `npm run icons`: PNG-иконки PWA (192, 512,
  маскируемая 512, apple-touch 180) из `public/icon.svg` в Chromium
  (шаблонный).
- `scripts/lib/harness.mjs` — обвязка кита (`maker-kit/harness`, её
  `docs/harness.md`) на портах clayform: 5281 для dev, 4281 для превью, со
  `--strictPort`. Перед `--preview` она сама пересобирает, а занятый порт
  превью — ошибка (сервер упавшего прогона иначе отдал бы старый `dist/`).
  `launch` → `app.open({ locale })` (страница в чистом контексте),
  `app.run` (закрывает браузер и сервер при любом исходе, ошибки консоли —
  провал), `throttle(page, rate)`, `horizontalOverflow`. Провал смоука
  называет свой шаг и кладёт кадр `smoke-fail.png` (в `--shots` или во
  временную папку). Браузер — Playwright по умолчанию либо из
  `PLAYWRIGHT_BROWSER` (путь к исполняемому chromium): в облачном контейнере
  Playwright ищет не ту сборку, что предустановлена.

## Архитектурные инварианты

- `src/geo/` — чистое ядро геометрии, **никогда** не импортирует Three.js.
- Ядро считает **в миллиметрах** (в отличие от mathsculpt с относительными
  единицами): у посуды реальные размеры — часть смысла; `encodeSTL` кита
  пишет миллиметры как есть.
- Ось модели — z, дно изделия в z = 0. Рендер сам поворачивает в y-up.
- Плоскость разъёма формы — XZ (y = 0). Ручка и носик обязаны лежать в ней:
  ручка при x < 0, носик при x > 0.
- Всё, что приходит извне (UI, файлы пресетов, localStorage), проходит
  `sanitizeState`. Санаторы не бросают ни на чём и идемпотентны — это
  проверяется тестами.
- CSG — WASM manifold-3d через мост кита (`maker-kit/csg/manifold`:
  `initCSG`, `toManifold`, `fromManifold`). Объекты Manifold не собираются
  GC: всё, что создано, держать в `CsgScope` и звать `dispose()`.
- **Главный поток не знает про WASM.** Весь CSG — в `src/worker/` и
  `geo/assemble.ts`, который зовёт только воркер; из `main.ts` не должно
  быть ни одного пути импорта в `maker-kit/csg/*` или `manifold-3d`.
  Проверяется глазами при правке импортов и в CI
  (`.github/workflows/deploy.yml`): в главном чанке `dist/assets/index-*.js`
  не должно встречаться слово `manifold`.
- Граница воркера — такая же внешняя граница, как файл пресета: задачу проверяет
  `isCsgJob` (`serveJobs` кита отвечает ошибкой на чужую, клиент не
  повиснет), а воркер сам зовёт `sanitizeState` на её состояние. Очередь —
  `WorkerClient` кита: одна дорожка, свежее превью вытесняет ждущее,
  экспорт (`kept`) превью не вытесняет.
- Отмена — `History` кита: шаг — законченная правка (`final` у контролов:
  отпущенный ползунок, выбранный пункт), кадры жеста — `live`. Таймера
  склейки нет. Undo и redo показывают состояние, которое история уже
  держит (`showState`), правка из панели — `applyState(next, final)`.
- Крышка (`geo/lid.ts`) — тело вращения целиком, включая обе ручки, поэтому
  CSG ей не нужен: `geo/lathe.ts` крутит замкнутый контур в осевом сечении.
  Считается за миллисекунды в главном потоке, воркер её не строит в превью;
  в экспорте — только ради общего пути с проверкой меша.
  Все диаметры посадки выводятся от полости тела (`lidFit`), а не задаются
  руками: крышка обязана входить именно в ту полость, которую строит
  `hollow.ts`, поэтому оба модуля меряют её одной функцией `cavityPoint`.
- Рельеф крышки — только на куполе: кольца купола в контуре несут нормаль и
  долю дуги (`LathePoint.relief`), `lathe` смещает их по `depthAt`. Юбка,
  поле и ручка остаются точными, у поля и ножки рельеф гаснет
  (`RELIEF_GUARD`). Волны тела идут на крышку через `lidRelief(state)`,
  накатка у крышки своя (`LidState.roulette`, «высота» — длина дуги купола,
  `lidDomeContext`).
- Выпуклость семейств (`plans/PLAN-SHAPE.md`): у горшка и вазы — абсолютная
  «Ширина» (`dBelly`, максимум силуэта ровно на контрольной точке), у
  чашки — `bulgeMm` над прямой стенкой (старый `barrel` в долях
  переводит `FamilyDef.legacy` внутри `clampFamilyParams`); высота —
  `bellyAt`/`bulgeAt`. Острота (`sharpness`, −1…+1) — перепараметризация
  высоты по обе стороны от пуза (`sharpWarp`, `sharpenAround`): радиусы не
  меняются, поэтому ширина остаётся максимумом. У миски вместо горба —
  колено (`kneeAt`, степень по высоте стенки). **Нейтральные значения
  (острота 0, `bulgeAt` 0.5, `kneeAt` 0.29) отдают силуэт байт в байт
  прежним** — на этом держатся golden и старые пресеты.
- Скругления дна (`baseFillet`, у всех семейств) и ножки (`footFillet`, у
  миски и вазы — у кого есть `FamilyDef.footZ`) — общая обработка силуэта в
  `buildProfile` катящейся окружностью (`filleted`). При нулевых радиусах
  силуэт ровно тот, что дало семейство, — golden этим и держится.
- Клеймо на донышке (`geo/mark.ts`, `AppState.mark`) — рельеф наружного дна
  изделия своей сеткой (`geo/bottom.ts`, `vesselBottom` в `geo/build.ts`),
  поэтому идёт всюду, где изделие: в печатное (а через него — в формы
  cast-builder). Строку рисует шрифтом **только главный
  поток** (`ui/markRaster.ts`, шрифты в `public/fonts`, лениво через
  `FontFace`) и отдаёт воркеру растром в задаче (`CsgJob.markStrip`, воркер
  проверяет размеры `sanitizeMarkRaster`); в состоянии растра нет. Лого —
  данные состояния (до 128 px). Читается снизу: ось x там зеркальна, угол —
  по часовой от «двенадцати»; тесты в `mark.test.ts` это стерегут. Дата — запомненная
  при галочке, `18.10.2026` при любом языке.
- Вогнутое дно (`geo/concave.ts`, `AppState.concave`) — осевое сечение
  наружного дна, ломаная от оси к краю плоского дна (радиус — нижнее
  кольцо сетки, то есть уже после «Скругления дна»). Сфера занимает всё
  дно; утопленное плоское оставляет на столе пояс ровно заданной ширины,
  оба угла ступеньки — один радиус. Считает его **одна** функция
  `concaveLayout`: её зовут сборка (`vesselConcave`/`vesselBottom` в
  `geo/build.ts`), `main.ts` (предупреждения, поле клейма, свесы) и график.
  Сетка дна идёт по сечению (`CapSpec.section` в `geo/bottom.ts`): кольца
  по длине и по повороту касательной — иначе крупный шаг срезал бы
  ступеньку фаской. Пол полости — сечение, смещённое на толщину дна по
  нормали (верхняя огибающая окружностей, `concaveFloor`): дно — пластина
  ровной толщины; полость с этим полом отдаётся в `HollowResult.cavity`, её
  же вычитает CSG. Клеймо — в утопленном круге (`markMm`), свод в процент
  свесов не идёт (`overhangFraction(…, skip)`). **Выключенное — меш байт в
  байт прежний**: `toBuildParams` поле не передаёт, golden и фикстуры
  cast-builder на этом держатся. Утопленное плоское глубиной 0 — то же:
  раскладки нет.
- Надписи на боку (`geo/decal.ts`, `AppState.sideText` / `sideImage`) —
  булевы тела, а не смещение сетки: шаг сетки (2,8 мм у горшка на 192)
  буквы не держит. Кадр надписи: x — дуга на высоте центра (буквы по
  меридианам), y — длина вдоль силуэта, z — по нормали; угол 0° — модельная
  −y («лицо» к камере открытия), плюс — к носику. Тела строит **только
  воркер** (`geo/decalSolid.ts`: контуры букв призмой, картинка полем
  высот, `refineToLength` и `warp` по стенке) в той же формуле, что ручку:
  `(оболочка ∪ ручки ∪ трубка ∪ выпуклое) − (полость ∪ канал ∪ вдавленное)`.
  Главный поток рисует их грубым оттиском (`BuildParams.decalProxy`) и по
  паузе берёт точную сборку. Под надписью и в 2 + 3 мм вокруг рельеф гаснет
  (`DecalField.calm`): стенка там — гладкий силуэт, и нулевой уровень поля
  высот отодвинут от неё на провис граней (`facetGapMm`). Вдавленное зажато
  стенкой до `MIN_WALL_MM` (`stateDecals`), выпуклое уходит в стенку на
  полстенки (не больше 1,5 мм), всё ниже 2 мм от дна, выше кромки и
  длиннее окружности обрезается (`DecalLayout.room`). Растр текста рисует
  главный поток (`ui/sideTextRaster.ts`) и шлёт воркеру в задаче
  (`CsgJob.sideText`, проверка `isTextRaster` кита). **Выключенные — меш
  байт в байт прежний**: `toBuildParams` поле `decals` не передаёт.
- Готовые узоры волны (`geo/wavePresets.ts`) — числа обеих волн как есть;
  список `#wave_preset` показывает узор, пока действующие числа совпадают
  (`wavePresetOf`), иначе «Свой». В состоянии узора нет.
- Размер оттиска накатки задаёт ширина пояска (и пропорции узора), а не
  просвет: шаг = элемент + просвет, округление числа оттисков достаётся
  просвету. Считается это в одном месте — `bandLayout`. Число оттисков
  руками больше не задаётся.
- **Видимый текст — только через словари `src/i18n/`.** `ru.ts` — эталон,
  из него выведен тип ключей `Key`; `en.ts` обязан повторить его ключ в
  ключ (`tsc`), параметры шаблонов сверяет `tests/i18n.test.ts`. Шаблоны:
  `{name}` и `{n|форма|форма|форма}` (порядок форм — категории
  Intl.PluralRules: у ru one/few/many, у en one/other; разбирает их `format`
  кита). Строки кита (`kit.*`: −/+, диалог пресетов, отказы файла, баннер,
  сито меша, лист, 🌐) вливаются в словари первыми — `{ ...kitRu, … }`,
  `{ ...kitEn, … }` — и проверяются тем же тестом. Тот же тест падает
  на любой кириллице в строковом литерале `src/` вне `ru.ts` — новая
  подпись мимо словаря не пройдёт.
- Ядро и воркер языка не знают: пользователю они говорят кодами
  (`geo/message.ts`: `Message` кита со своими кодами и `kit.*`; код обязан
  быть ключом словаря — это проверяет `tm`). Предупреждения, сито меша
  (`kit.mesh.*`), этапы прогресса — всё так; в список сообщений строки
  уходят с `data-code`. Подписи параметров
  семейств — `param.<семейство>.<key>`, общий запас `param.<key>`.
  Внутренние `throw` ядра — по-английски, это сообщения разработчику.
- Контролы (`Control<T>` — китовые строки плюс своя строка картинки,
  `ui/controls.ts`), карточки и пункты списков хранят **ключи**, а
  переводятся при отрисовке. Смена языка — `renderPanel()` в `main.ts`
  заново плюс `syncPanel()`: состояние, история, камера, свёрнутость
  карточек и прокрутка остаются. Обработчики на статической разметке
  поэтому ставятся один раз или свойством (`onclick`), иначе копились бы.
- Язык живёт в модуле `i18n`, а не в `AppState`: в файл пресета он
  не попадает. Переключает его 🌐 кита (`ui/languagePicker`). Выбор —
  `localStorage` `clayform_lang`, без него — первый
  поддерживаемый из `navigator.languages`, иначе en. В `index.html` текст
  английский, русский подставляет `data-i18n` / `-title` / `-aria`.
- Текущее изделие живёт в браузере: запись кита `clayform_project`
  (`state/project.ts`: изделие, открытый пресет, данное имя), пишется после
  каждой законченной правки, отмены, смены пресета или имени
  (`keepProject`), открывается при запуске. Ссылки 🔗 с состоянием больше
  нет (`plans/PLAN-DECOR.md`): старая `#s=` в адресе ничего не значит. Сбой
  записи — в баннере кита, пока длится. Так перезагрузка на новую версию
  (PWA) теряет только историю отмены.
- Встроенный пресет узнаётся по `id`, имя и подсказка — в словаре
  (`preset.<id>`, `preset.<id>.note`). Свои пресеты не переводятся и
  узнаются по id `u<n>` (`core/presets` кита): запись
  `clayform_user_presets_v1` версии 1 — `{ version, presets }`; голый
  список старых версий читается как версия 0 и получает id. 💾 под занятым
  именем заменяет тот пресет (id и место остаются), переименовывают в
  диалоге. Автоимя по языку («Изделие N» / «Piece N»), нумерация общая
  (`nextPresetName` с приставками всех языков и старым «Моё»). 📄 открывает
  пустой пресет кита `BLANK_PRESET` (`{ id: 'blank', listed: false }`,
  `defaultState()` под именем «Новое изделие» / «New piece»): в списке его
  нет, по ссылке `b:blank` находится, один шаг отмены. ● на кнопке
  имени — изделие ушло от пресета (`presetSignature`: без детализации и
  «крышки рядом»).

## Что сколько стоит

Замерено на M1 Mac, сетка 192×192 (74 тыс. треугольников):

| Операция | Время |
|---|---|
| сборка изделия (параметрическая) | 10 мс |
| полое изделие с вогнутым дном | +1–2 мс на сетке 192, +10 мс на 384 (сечение, огибающая пола, дно своей сеткой) |
| сборка крышки (латэ, без CSG) | 1–2 мс |
| полное `validateMesh` | 60 мс |
| CSG: полое изделие с ручкой и носиком | ~2 с; на сетке 128 — 0,8 с |
| экспорт изделия с ручкой на 384 | ~10 с (в воркере, вкладку не держит) |
| экспорт чайника с ручкой, носиком и крышкой на 192 | ~2,5 с (смоук; до кадров по запросу вьюера кита было 3,0–3,6) |
| точная сборка изделия (превью, сетка 128) | ~1,1 с после быстрого вердикта (смоук) |
| чашка с текстом на боку, сетка 96: оболочка, контуры букв, изгиб, булевы | ~0,5 с (vitest, `decalSolid.test.ts`) |
| экспорт изделия с текстом и картинкой 256 px на 192 | ~2,4 с (смоук, шаг «Надписи») |
| растр текста на боку (главный поток) | единицы мс; кэш по шрифту, кеглю и строкам |
| `tsc --noEmit` (TypeScript 7) | 0,3 с (на TS 5 было 2 с) |
| `oxlint --type-aware` | 0,4 с |

Вес сборки: наш код с китом 180 КБ (из них ~45 КБ исходника — два словаря
i18n, ~20 КБ — модули интерфейса кита; надписи на боку, пресеты волн и
растры кита добавили 28 КБ; шрифты клейма ~120 КБ лежат отдельно и
грузятся только с клеймом), Three.js 505 КБ (125 КБ gzip), WASM
manifold 542 КБ — и он грузится только воркером и только под CSG, вкладку не
задерживает. Three ужать нечем и это проверено: `import * as THREE` и
поимённый импорт дают байт в байт одно и то же, тряска дерева уже отработала,
а внутри WebGLRenderer с библиотекой шейдеров. Отдельным чанком он вынесен
ради кэша, не ради веса (см. комментарий в `vite.config.ts`).

Отсюда раскладка. В главном потоке — только параметрика: изделие
пересобирается на каждое движение ползунка, проверка меша откладывается на
220 мс. Всё, что требует булевых операций, уходит в воркер через
`WorkerClient` кита (`worker/client.ts`) — точное превью изделия с
задержкой в 400 мс и на огрублённой сетке, экспорт по кнопке на
`state.resolution`. Очередь — одна дорожка: бегущую задачу
не прервать (WASM посреди операции не останавливается), ждущую вытесняет
свежая — это и заменяет прежнюю гонку со `stamp`, который в `main.ts` остался
вторым рубежом.

Превью изделия двухступенчатое, и это не украшательство. Пока ползунок в
движении, ручка и носик рисуются отдельными мешами — снаружи это выглядит
ровно как их объединение, а стоит 10 мс вместо секунды. Но только снаружи:
внутри полости торчат утопленные торцы ручки, а носик стоит заглушенным,
и человек справедливо считает это браком модели. Поэтому по паузе
`showExactVessel` заказывает воркеру настоящую сборку — ту самую, что уходит
в STL, — и подменяет ею картинку, заодно перепроверяя меш. Сетка у точной
сборки огрублённая (`EXACT_SEGMENTS`): показать надо срезанные торцы и
сквозное устье, а силуэт и так нарисован на полной.

## Идентификаторы контролов

Схема кита: `<приставка>_<ключ>` — сам контрол, `_n` — точное поле
ползунка, `_dec` / `_inc` — его −/+, `_note` — заметка под строкой.
Включение эффекта — строка-галочка внутри карточки: `#wave_on`,
`#wave2_on`, `#roulette_on`, `#handle_on`, `#spout_on`, `#lid_on`,
`#mark_on`; карточка — `#card_<id>`, её шапка `.fcard-head` только
сворачивает. Подблок — складная карточка внутри карточки: `#card_wave2` в
`#card_wave`, `#card_markLogo` в `#card_mark`, `#card_concave` в «Форме».
Смоук включает эффект `setOn(id, on)` (раскрыв карточку и внешнюю), а
`snap.mjs` раскрывает свёрнутые карточки перед действием над их контролом.
Готовый узор волны — `#wave_preset` (`''` — «Свой», `ripple`, `flow`,
`basket`, `flame`, `swirl`; `geo/wavePresets.ts`).

Форма: высота — `#p_heightMm`, параметры семейства — `#p_<key>`.
Скругления: `#p_baseFillet`, `#p_footFillet`. Выпуклость:
`#p_dBelly/_bellyAt` (горшок, ваза), `#p_bulgeMm/_bulgeAt` (чашка),
`#p_sharpness` (все три), у миски `#p_curvature/_kneeAt`.

Полосы накатки — список кита: строка полосы `#roul_0` с ✕ `#roul_0_remove`,
«+ Полоса» — `.add-button` карточки, подпись полосы — `.band-note`.
Ползунки полосы нумеруются по её индексу в приставке: `#roul0_pattern`,
`#roul1_depth` и т. д. `#roul*_gap` показывается только у одиночных узоров
(точки, ромбы, насечки, картинка). Вид меандра — `#roul*_meander` (только у
меандра). Узор-картинка — `#roul*_image` (скрытый `<input type=file>`) и
`#roul*_invert`.

У носика два вида в одной карточке: `#spout_kind` переключает, а ползунки
показываются по условию `when` — `#spout_pull/_width/_zone` для оттянутого
края, `#spout_attach/_length/_tip/_base/_tipD/_angle` для трубчатого.

Крышка — `#lid_on` и ползунки `#lid_recess/_depth/_ledge/_clearance/_field/`
`_dome/_curvature`, ручка — `#lid_knob` (select) и `#lid_knobD/_stemD/_stemH`,
плюс `#lid_capH` только для ручки-Т и `#lid_knobFlat` (сплющенность) только
для шара — по тому же `when`. Накатка на куполе — свои полосы
(`#lidroul_0`, `#lidroul0_pattern` и т. д.); волны идут на крышку галочками
`#wave_onLid` / `#wave2_onLid`.

Надписи — группа `#decorCards`: `#card_text`, `#card_image`, `#card_mark`.
Текст: `#text_on`, `#text_text` (textarea), `#text_font`,
`#text_size/_angle/_height/_depth`. Изображение: `#image_on`, `#image_file`
(file input), ✕ `#image_fileRemove`, `#image_invert`,
`#image_size/_angle/_height/_depth`.

Клеймо: `#mark_on`, `#mark_text` (текст — `--set` в `snap.mjs` его
заполняет), `#mark_font`, `#mark_date`, `#mark_start/_size/_margin/_depth`;
подблок `#card_markLogo`: лого `#mark_logo` (file input), ✕
`#mark_logoRemove`, `#mark_logoInvert/_logoAngle/_logoSize`; камера на дно —

Вогнутое дно: подблок `#card_concave` внизу карточки «Форма» (складная
карточка кита внутри `.card`), `#concave_on`,

Экспорт: `#print_wall/_base/_rim`, детализация `#print_resolution`,

Шапка: `#presetBtn` (имя проекта, `.changed` — ● ушло от пресета)

## Чего в v1 нет

- Сита в основании носика: канал идёт ровной конической трубкой, дырчатую
  перегородку сверлят по сырому.
- Раздельной детализации превью и экспорта: список «Детализация» влияет
  только на экспорт.
- Отдушины в крышке: у чайника она нужна, но сверлят её по сырому.
- Остальных вариантов меандра с `references/meander-variants.png` (сейчас
  шесть: ключ, в рамке, спираль, крючки, Т-зубцы, П-волна) — добавляются
  ASCII-сеткой в `MEANDER_GRIDS` и строкой в `MEANDER_OPTIONS`.
- Детализации пояска отдельно от сетки: картинка накатки мельче узла сетки
  не видна (горшок ⌀170 на 192 сегментах — 2,8 мм на узел). Картинке на
  боку это не грозит: она — тело воркера своим шагом.
- Фиксатора крышки от выпадения при наливе — ни байонета, ни выступа.
- Клейма на крышке и выпуклого клейма: только вдавленное, только на дне.
- Надписей на крышке; второго текста или второй картинки на боку;
  выравнивания строк текста не по центру; шрифтов, кроме четырёх клеймовых.
- Уклона у стенки ступеньки вогнутого дна (она отвесная), пояса у сферы и
  вогнутости у крышки.
