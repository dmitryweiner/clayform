# Что осталось от первоначального плана

Сверка `PLAN.md` с тем, что реально лежит в коде на 2026-08-21. Все вехи
M0…M8 пройдены и приложение работает целиком; ниже — хвосты, которые в план
входили, а в код не попали, и открытые вопросы, оставшиеся открытыми.

Проверено чтением исходников, а не по памяти.

---

## 1. Явный мусор и сломанное

Мелочи, но это именно дефекты, а не «не успели».

### 1.1 `npm run shot` ссылается на несуществующий файл

`package.json` содержит `"shot": "node scripts/shot.mjs"`, а самого
`scripts/shot.mjs` нет (`PLAN.md` §0.1 обещал перенести его из mathsculpt).
Команда падает.

Решать одним из двух: либо написать скрипт (снимок каждого пресета в
`./shots` — полезно для README и для глаза при рефакторинге), либо убрать
запись из `package.json`. Второе честнее, если снимки не нужны: `snap.mjs`
уже умеет `--preset`.

### 1.2 Мёртвый индикатор прогресса

`index.html` содержит `#progressWrap` / `#progressBar` / `#progressFill`,
в `style.css` под них написаны правила, но **никто их не трогает**: в
`main.ts` нет ни одного обращения.

При этом место для них есть: сборка оснастки занимает сотни миллисекунд, а
экспорт ванночек на высокой детализации — секунды, и сейчас об этом
сообщает только надпись «Собираю…» на кнопке. Либо оживить, либо вычистить
разметку.

### 1.3 Пустая директория `src/worker/`

Осталась от M0, когда воркер ещё планировался. Файлов внутри нет.

## 2. Из плана не сделано

### 2.1 Приставной носик (`applied`)

`PLAN.md` §4.4 описывал два вида носика: `lip` (оттянутый край) и `applied`
(накладной конический желобок, объединяемый через CSG). Сделан только
первый — `SpoutState` даже не имеет поля `kind`.

Оттянутый край покрывает крынку, кувшин и ойнохойю, то есть большинство
референсов. Трубчатый носик нужен для чайника; машинерия для него уже есть
(`sweep.ts` + `unionAll`), работы примерно как на ручку.

Пользователи: Очень желательно.

### 2.2 Фланец разъёма у мастер-позитива

`PLAN.md` §4.6.3: «изделие ⊔ spare ⊔ **опциональный фланец по плоскости
разъёма** (упрощает ручную укладку пластилина)». `buildMaster` строит
изделие с горловиной и всё.

Без фланца при ручном изготовлении силиконовой формы пластилиновую постель
приходится выкладывать на глаз — а это ровно тот шаг, который в
`slip_casting_mold_workflow.md` §5 назван самым муторным.

Пользователи: Решено не делать.

### 2.3 Скруглённые наружные рёбра гипсового блока

## 3. Открытые вопросы плана, оставшиеся открытыми

### 3.1 (§7.1) Производительность CSG на предельной детализации

Замерено до 384×384 (`CLAUDE.md`, раздел «Что сколько стоит»), 512 не
проверялось — и в списке `RESOLUTIONS` его нет. Таймингов экспорта оснастки
в доке тоже нет, только превью.

### 3.2 (§7.3) Поведение «ролик поверх ручки» не зафиксировано в доках

Рельеф и накатка применяются к телу вращения **до** объединения с ручкой,
поэтому на самой ручке узора нет. Это осознанно, но написано об этом только
в `PLAN.md` §7 как о вопросе — ни в README, ни в UI пояснения нет.

Пользователи: Так и должно быть, можно обновить README.

### 3.3 (§7.4) UX бочкообразной чашки не проверен с пользователем

Анализатор при `barrel > 0` переключает чашку с одночастной формы на
половины и пишет почему. Тест на это есть; смотрел ли на это живой человек —
нет.

Пользователи: Проверено, отлично работает!

### 3.4 (§7.5) Двухчастная силиконовая форма для мастера

v1 печатает только сам мастер-позитив; силиконовую форму с него снимают
вручную по `slip_casting_mold_workflow.md` §5–6. Автоматическое построение
опалубки и постели под мастер в план входило как «возможно потом».

Пользователи: Решено не делать.
