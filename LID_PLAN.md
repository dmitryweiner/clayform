# LID_PLAN.md — крышка

Отдельная печатаемая деталь + фланец-посадка в горловине тела. Решения
приняты с пользователем 2026-08-22:

1. **Посадка — одна схема** с параметром «утопление» `recessMm`:
   0 — поле крышки лежит на венчике (классический чайник), >0 — полочка
   утоплена ниже края (галерея). Никаких двух режимов.
2. **Оснастка для крышки — в этот же заход**: перевёрнутая (юбкой вверх)
   крышка проходит через существующий конвейер `analyzeMold →
   buildMaster/buildBaths` как второе изделие; её детали добавляются в общий
   список экспорта.
3. **Фланец в форме тела** — пробойником: горловина-пробойник сужается до
   диаметра посадки, стенка у устья выходит толще, а точную полочку и цилиндр
   доводят по сырому (та же логика, что у сита в носике). Записать в «чего в
   v1 нет». Дополнение (2026-08-22): реализовать и упрощённую ответную часть
   **без полочки** — см. вариант Б в разделе про фланец; какой станет
   дефолтом, решаем по ходу реализации.
4. **Превью** — крышка надета на изделие. В списке деталей и в экспорте —
   отдельная деталь со своим z = 0.
5. Носик «оттянутый край» с крышкой несовместим (вытяг ломает круглый
   венчик) — **молча гасится**, без предупреждений. Трубчатый носик и ручка
   не мешают.

## Геометрия

### Система размеров посадки

Всё выводится от горловины тела, чтобы крышка подходила всегда, без ручной
подгонки диаметров. Обозначения (мм, до усадки):

- `rCav` — радиус полости тела у венчика: `offsetPoint(silhouette, wallMm)`
  в верхней зоне; берётся **минимум** по полосе `[H − recess − depth, H]`,
  иначе у сужающегося горла юбка не пролезла бы через самое узкое место.
- `ledgeMm` — ширина полочки (параметр крышки): `rSeat = rCav − ledgeMm`.
- `clearanceMm` — зазор посадки (параметр): `rPlug = rSeat − clearanceMm`.
- `fieldMm` — вынос поля за посадку (параметр): `rField = rSeat + fieldMm`.
  При `recessMm > 0` зажать `rField ≤ rCav − clearanceMm` — поле обязано
  пролезть в устье. При `recessMm = 0` ограничение только сверху разумным
  максимумом (поле может нависать над венчиком, фото 12–13).

Если `rSeat` получился меньше ~6 мм — горловина слишком узкая; посадку
зажать и выдать предупреждение в общий список (`baseWarnings`), крышку не
отключать: пользователь сам увидит и расширит горло.

### Фланец тела (правка `buildHollowVessel`) — два варианта, решить по ходу

**Вариант А — с полочкой** (полный, как на фото 14). Ложка дёгтя: гипсовая
форма полочку не отольёт, из формы изделие выходит без неё, полочку доводят
по сырому. Для прямой печати честен полностью.

**Вариант Б — без полочки** (проще). Внутренняя поверхность горловины просто
цилиндризуется: `rSeat = rCav` (минимум радиуса полости по полосе посадки),
стенка не утолщается, ступеньки нет. Крышку держит только поле, лежащее на
венчике — `recessMm` в этом варианте не работает (утопить крышку не на что),
юбку ведёт цилиндр. Зато шликерная отливка выходит из формы **готовой**: 
пробойник диаметром `rSeat` формирует ровно эту геометрию, доводка по сырому
не нужна. Именно так устроено большинство простых чайников (фото 12–13).

Решение отложено до реализации. Параметризовать так, чтобы Б был вырожденным
случаем А: при `ledgeMm = 0` полочка исчезает сама (`rSeat = rCav`), при
`recessMm = 0` — верхняя ступень; отдельной ветки в коде не заводить.
Практический план: минимум ползунка «полочка» опустить до 0, дефолт выбрать
по результату на превью; если полочка остаётся в v1 — предупреждение в
режимах форм («полочку доводят по сырому»), если нет — ползунки `ledge` и
`recess` не показывать вовсе (убрать из карточки, оставить в состоянии
про запас).

Профиль полости сверху вниз при включённой крышке (вариант А; Б — то же с
`ledge = 0`, `recess = 0`):

```
z = H … H−recess          r = rCav      (обычная полость, стенка как была)
z = H−recess              полочка: горизонтальное кольцо rCav → rSeat
z = H−recess … −depth     r = rSeat     (цилиндр — направляющая юбки)
ниже                      конус-переход к обычной полости, ~45°
```

При `recess = 0` верхняя ступень вырождается и полочкой становится сам торец
венчика — непрерывный переход, отдельной ветки в коде быть не должно.

Реализация: в `hollow.ts` внутренние кольца уже строятся по `offsetPoint`;
добавить функцию `seatOverride(z): number | null`, который в полосе посадки
возвращает `rSeat`, на полочке даёт резкий шаг (двумя кольцами с почти
одинаковым z — сетка это переживает, как переживает плоский пол), ниже —
`max(rSeat, обычный офсет)` до пересечения с конусом. Заглаженный венчик
(`rimRadiusMm`) остаётся как есть: дуга кромки соединяет наружную стенку с
`rCav`, а не с посадкой.

Осторожно с `previousZ`-монотонностью в цикле полости: полочка — это шаг
радиуса при почти постоянном z, монотонность по z не нарушается.

### Крышка: чистое тело вращения, без CSG

Ключевое наблюдение: и сама крышка, и обе ручки (шар, Т) осесимметричны,
поэтому вся крышка — **один латэ по замкнутой ломаной** в плоскости (r, z).
Никакого manifold: строится параметрически в главном потоке за миллисекунды,
как тело изделия. Это отличает её от ручки/носика — тем нужен был CSG, тут
нет.

Существующий `vesselGrid` — это r(z), функция; профиль крышки функцией не
является (горизонтальный низ поля: много r при одном z). Нужен новый
примитив в `geo/`:

```
lathe(points: {r, z}[], nu): SurfaceMesh
```

— замкнутая ломаная, обход по часовой в (r, z) → нормали наружу; точки с
r ≈ 0 (вершина ручки, центр полости под куполом) схлопываются в веер на оси.
Класть в `geo/lid.ts` или отдельным `geo/lathe.ts` — решить по объёму; тесты
на замкнутость и объём обязательны (validateMesh: watertight).

Контур печатной (полой) крышки, от низа юбки наружу и обратно внутрь:

```
низ юбки (r = rPlug − t, z = 0) → наружу юбки (rPlug) → вверх на depth →
низ поля наружу до rField → скругление/торец поля → купол вверх до ножки
ручки → ручка (шар или Т) → ось (r=0, вершина) →
[внутренний путь] ось под куполом → офсет купола внутрь на t →
внутренняя стенка юбки (rPlug − t) → низ юбки
```

- `t` — толщина стенки крышки: берём `hollow.wallMm` тела, отдельного
  ползунка не заводить (печатают тем же соплом; та же логика, что у стенки
  носика).
- Полость повторяет только купол; ручка остаётся сплошной, полость под ней
  закрывается на оси.
- Купол: как у миски — `domeMm` (высота, мм) и `curvature` 0…1 (0 — конус,
  1 — дуга, встающая к краю вертикально); переиспользовать формулу BOWL
  (`lerp(s, sqrt(1−(1−s)²), c)`), не копипастой, а вынести хелпер или
  честно продублировать три строки с комментарием — смотреть по месту.

Ручка (осесимметричная, поверх купола):

- `knobKind: 'ball' | 'tee'`;
- общее: `knobDMm` (⌀ шляпки/шара), `stemDMm` (⌀ ножки), `stemHMm` (высота
  ножки);
- 'ball': ножка-цилиндр + шар ⌀ `knobDMm` (в контуре — дуга);
- 'tee': ножка + плоский диск ⌀ `knobDMm` толщиной `capHMm`, рёбра слегка
  фаской/дугой, чтобы латэ не давал игольных треугольников.

Сплошная крышка для оснастки — тот же контур без внутреннего пути (полость
не вырезается): `buildLidSolid` рядом с `buildLidMesh` в том же модуле.

### Состояние

`geo/lid.ts`:

```ts
interface LidState {
  on: boolean;
  recessMm: number;      // 0..20, def 0
  depthMm: number;       // юбка, 3..30, def 8
  clearanceMm: number;   // 0.2..2, def 0.6
  ledgeMm: number;       // полочка, 0..10; 0 — вариант Б, дефолт решить по превью
  fieldMm: number;       // поле за посадку, 0..30, def 6
  domeMm: number;        // 3..80, def 18
  curvature: number;     // 0..1, def 0.6
  knobKind: 'ball' | 'tee';
  knobDMm: number;       // 8..40, def 18
  stemDMm: number;       // 4..20, def 8
  stemHMm: number;       // 2..25, def 7
  capHMm: number;        // 2..12, def 4 (только tee)
}
```

`defaultLid()` / `sanitizeLid()` по образцу spout: никогда не бросает,
идемпотентен, старые ссылки без поля lid получают дефолт (on: false) — 
STATE_VERSION не трогаем. Перекрёстные ограничения (`rSeat` от горловины,
`stemDMm < knobDMm`) — часть в санаторе (`stemDMm = min(stemDMm, knobDMm)`),
часть только на сборке с предупреждением: санатор не знает семейства.

В `AppState` — поле `lid: LidState`, прокинуть через `sanitizeState`.
В `toBuildParams` крышку НЕ включать: `BuildParams` — про тело вращения
изделия, а крышка строится своим вызовом от готового профиля
(`buildLid(profile, heightMm, hollow, lid)` → размеры посадки + меши).

### Гашение оттянутого носика

Не мутировать состояние (иначе выключение крышки не вернёт носик).
Хелпер в `geo/lid.ts` или в schema:

```ts
effectiveSpout(state): SpoutState  // lid.on && kind==='lip' → {...spout, on:false}
```

Звать во всех потребителях: `refresh()` в main, `vesselPart`/`moldParts` в
воркере, `toBuildParams` — удобнее всего прямо в `toBuildParams` (он и так
единственный конструктор BuildParams) плюс в двух местах, где spout читается
мимо него (`buildAppliedSpout` в превью, `hasAppliedSpout`). Проверить
`mouthOf`: pullAt у погашенного носика должен быть нулевым — станет сам,
если гасить в toBuildParams. В карточке носика — ничего не показывать
(решение «молча»), но однострочный hint в карточке крышки не повредит.

## main.ts (превью)

- Быстрый путь: `buildHollowVessel` уже с фланцем (lid прокинут);
  `buildLidMesh` → перенос на `z += H − recessMm − depthMm` (юбка садится в
  цилиндр) → в `scene.setMeshes` рядом с телом, ручкой, носиком.
- Точный путь (`showExactVessel`): воркер возвращает тело + крышку двумя
  деталями; крышке CSG не нужен, но собрать её в воркере всё равно (см.
  ниже) — тогда точное превью просто ставит обе детали, крышку — с тем же
  переносом. Аудит гонять по обеим: `validateMesh` дёшев для крышки.
- Список деталей режима «изделие»: `[Изделие, Крышка]` с пометкой объёма.
- Статус-строка: габарит оставить по телу (крышка надета — высота
  фактически та же с точностью до ручки; не усложнять).
- Предупреждение «горловина узка для посадки» — в `baseWarnings`.

## Воркер

- `vesselPart` → `vesselParts`: тело как раньше (CSG), крышка —
  `buildLidMesh` со своим z = 0 (в экспорт деталь уходит НЕ надетой, печатают
  отдельно). Валидация обеих под экспорт. Прогресс: +1 этап.
- `moldParts`: после деталей тела — детали крышки:
  1. `buildLidSolid` → перевернуть (z → lidH − z, зеркалит винding —
     не забыть развернуть индексы треугольников);
  2. `analyzeMold(перевёрнутая крышка, {hasHandle: false, hasSpout: false})`
     — шейка ручки даёт поднутрение, анализатор сам выберет половины;
  3. `mouth` крышки = юбка сверху: `{ zMm: lidH, radiusMm: rPlug }`;
  4. `buildMaster` / `buildBaths` как для тела; id/label с префиксом
     `lid-…` / «Крышка: …».
  Прогресс: MAX_MOLD_PARTS теперь 3 + 3; total уточняется после обоих
  анализов, шкала по-прежнему только вперёд.
- Пробойник тела по посадке: в `mouthOf` при включённой крышке отдавать
  `radiusMm = rSeat` (а не наружный венчик). `buildCavity` менять не надо —
  он и так строит горловину по `mouth.radiusMm`. Проверить глазами превью
  ванночек: воротник должен стать уже устья.

## Грабли, о которых помнить

- Латэ: точки на оси (r≈0) — веер, не кольцо; дубли вершин на стыке обхода
  u = 0/2π склеить, иначе validateMesh увидит незамкнутость.
- Переворот крышки для оснастки зеркалит нормали — развернуть индексы.
- Полоса `rCav` берётся минимумом по всей глубине посадки, не по венчику:
  у горшка с горлом уже устья юбка иначе упрётся.
- `rimFlare` у тела может задирать `rCav` у самого венчика — минимум по
  полосе это тоже покрывает.
- Крышка в превью надета, в экспорте — со своим z = 0: не перепутать, где
  какой перенос.
- Усадка: и посадка тела, и крышка масштабируются одним `shrinkPct`, зазор
  `clearanceMm` задан в сырых мм — при усадке он усядется тоже; это
  правильно (посадку подгоняют по сырому), отдельно не компенсировать.
