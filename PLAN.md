# ClayForm — план реализации

Веб-приложение для параметрического моделирования глиняной посуды с экспортом STL
в трёх режимах: (1) полое изделие для прямой печати, (2) мастер-позитив для
классического изготовления силиконовой формы, (3) «ванночки» под заливку силикона —
по одной на каждую часть будущей гипсовой формы для шликерного литья.

Решения, принятые с пользователем (2026-08-20):

- **Формы v1**: все 4 семейства — горшок/крынка/корчага, миска/тарелка/пиала,
  чашка/стакан/кружка, ваза/амфора/бутылка.
- **Ручки и носики — сразу в v1**, с собственными параметрами.
- **Оснастка — оба режима**: мастер-позитив и ванночки под силикон.
- **Разъём формы — автовыбор по геометрии**: открытые формы без поднутрений →
  одночастная drop-out форма; закрытые → 2 вертикальные половины (+ дно при
  необходимости). Приложение само анализирует поднутрения.
- Методология: **TDD** (vitest, red → green → refactor, golden-тесты как в mathsculpt).
- Инфраструктура целиком из `../mathsculpt` (Vite + TS + Three.js + vitest +
  playwright smoke/shot, деплой в `./docs` для GitHub Pages).

## 0. Ключевые архитектурные решения

### 0.1 Что берём из mathsculpt как есть (копированием, не зависимостью)

| Модуль | Судьба |
|---|---|
| `geo/surface.ts` (сетка u,v, sampleGrid, assembleMesh/HollowMesh, крышки) | как есть |
| `geo/normals.ts` | как есть |
| `geo/stl.ts` (бинарный STL, мм) | как есть |
| `geo/validate.ts` (watertight, объём, export gate) | как есть |
| `geo/profiles.ts` (Эрмит по контрольным точкам) | база — поверх строим параметрические профили посуды |
| `geo/displace.ts` | урезаем: остаются только волна и волна² + новый roulette |
| `geo/deform.ts` | урезаем до нужного (сглаживание; деформация венчика для носика) |
| `worker/build.ts`, `render/scene.ts`, `state/{schema,share,userPresets}.ts`, `ui/*` | адаптируем |
| `scripts/smoke.mjs`, `shot.mjs`, конфиги (vite, tsc, eslint, vitest) | как есть |
| Golden-тесты `UPDATE_GOLDEN=1` | тот же механизм |

Инвариант mathsculpt сохраняем: **geo-ядро не импортирует Three.js**, все
геометрические функции чистые и детерминированные.

### 0.2 Булевы операции — `manifold-3d` (WASM)

Ручки/носики и построение оснастки требуют CSG над мешами. Писать свой mesh
boolean — нереалистично. Берём [`manifold-3d`](https://www.npmjs.com/package/manifold-3d)
(Apache-2.0, WASM, гарантирует manifold-выход, используется в OpenSCAD/BRL-CAD).

Где нужен CSG:

- union: тело ⊔ ручка ⊔ накладной носик;
- mold: блок гипса − полость изделия − горловина + ключи;
- ванночка: опалубка − мастер-блок (фактически негатив);
- разрез изделия/блока плоскостью разъёма (`trimByPlane`/`splitByPlane`).

Тела вращения с рельефом продолжаем строить **параметрически** (быстро, полный
контроль детализации рельефа), в Manifold передаём готовые меши. Marching cubes
не используем — рельеф ролика потребовал бы недостижимой резолюции вокселей.

Риск: WASM в worker'е + браузере — проверить загрузку в vite (M1, спайк-тест).

### 0.3 Представление изделия

Изделие = **сплошной позитив** (solid of revolution с рельефом) ⊔ ручка ⊔ носик.

- Для литья используется именно позитив: толщину стенки в шликерном литье задаёт
  время выдержки, а не модель.
- Для прямой печати полость строим как в mathsculpt (`assembleHollowMesh`,
  стенка в мм) — но только для тел **без ручек** (ручка полой печатной версии —
  сплошная, union к полому телу).

Ось — z, низ в z=0 (печатная конвенция mathsculpt). Единицы ядра — мм сразу
(в отличие от mathsculpt): у посуды реальные размеры — часть смысла.

### 0.4 Плоскость разъёма

Плоскость XZ (y=0), проходит через ось. **Ручка и носик обязаны лежать в
плоскости разъёма** (ручка сзади, носик спереди — как в реальном литье кувшинов).
Это фиксируем в модели: у ручки/носика нет параметра «угол вокруг оси», только
сторона. Рельеф/ролик по θ — произвольный, но анализатор поднутрений проверяет
его совместимость с направлением разъёма (см. 4.3).

## 3. Семейства форм и их параметры

Каждое семейство — функция `params → ProfileDef` (контрольные точки Эрмита,
как в mathsculpt, но точки вычисляются из осмысленных параметров, а не фикс).
Все радиусы/высоты — мм.

| Семейство | Параметры (кроме height) |
|---|---|
| **pot** (горшок/крынка/корчага) | dNeck, dBelly, dFoot, bellyHeight (t), shoulder (резкость плеча), rimFlare (отгиб венчика) |
| **bowl** (миска/тарелка/пиала) | dTop, dFoot, curvature (прямая↔пиала), footHeight, rimThickFlare |
| **cup** (чашка/стакан/кружка) | dTop, dBottom, barrel (бочкообразность), taperBias |
| **vase** (ваза/амфора/бутылка) | dNeck, dBelly, dFoot, bellyHeight, neckHeight, rimFlare, footFlare |

Валидация параметров: клампы + инварианты (горло > 0, дно печатаемое ≥ 20 мм и
т.п.) — чистые функции, тестируются первыми.

Пресеты: на каждое семейство 3–5 именованных пресетов по референсам
(крынка, корчага, амфора, килик, пиала…).

## 4. Геометрические подсистемы

### 4.1 Рельеф (relief.ts)

Смещение по нормали поверхности вращения (механика `displace.ts` mathsculpt):

- `wave(u,v)`: A·w(f·x + φ), где x ∈ {v, u, v + k·u}, w — sin / треугольник /
  меандр (сглаженный) / скруглённый; зона по высоте с fade-краями.
- `wave2`: волна, у которой амплитуда и/или фаза сами промодулированы второй
  волной (перенос идеи mod-matrix mathsculpt в один параметрический блок).

### 4.2 Ролик (roulette)

Имитация колеса-штампа по вращающемуся изделию: периодическая функция глубины
`p(s, t)` на тайле, повторённая `N` раз по окружности пояса высотой bandWidth.

- `repeats: auto` — N = round(2πR_band / желаемый шаг тайла) → узор замыкается
  без шва **всегда**; ручной N тоже квантуется до целого.
- Паттерны — чистые функции тайла: rope (наклонные валики), zigzag, dots
  (решётка углублений), diamonds, chevron, dashes.
- Глубина со знаком: вдавленный или выпуклый узор.
- Наклон angle — сдвиг фазы тайла по высоте (спиральный накат).

### 4.3 Ручка (handle.ts)

- Плоская кривая в плоскости y=0: кубическая Безье от точки крепления
  attachTop до attachBottom на поверхности тела, вынос offset, форма shape.
- Свип овального сечения (thickness × thickness·widthRatio) вдоль кривой,
  концы утоплены в тело (запас на надёжный union).
- `count: 2` — вторая ручка зеркально (амфора). Обе — в плоскости разъёма.
- Union через manifold. Проверка: кривая не пересекает ось и не выходит за
  печатный габарит.

### 4.4 Носик (spout.ts)

- `lip` (по умолчанию): деформация венчика — локальный вытяг верхней кромки
  наружу-вниз (классический слив кувшина). Реализуется деформером верхних
  рядов сетки, CSG не нужен.
- `applied`: накладной конический желобок, union'ом (как ручка).
- Всегда при x>0 в плоскости разъёма (ручка при x<0).

### 4.5 Анализ поднутрений и схема разъёма (mold/analyze.ts)

Вход: позитив изделия (+ горловина). Выход: `MoldScheme`.

1. **drop-out (1 часть)**: возможна, если для направления вытяжки +z все
   нормали поверхности удовлетворяют n_z ≥ −ε с учётом конусности, нет ручек,
   венчик — максимальный диаметр. (Миски, тарелки, конические стаканы.)
2. Иначе **halves (2 половины)**: вытяжка ±y. Проверяем на сетке: для точек
   с y>0 требуется n_y ≥ −ε (аналогично y<0). Рельеф/ролик могут нарушать —
   каждое нарушение репортим (величина, зона) как warning с порогом блокировки.
3. **+bottom (3-я часть)**: если дно имеет ножку/подрез (footFlare, footHeight),
   низ отделяется горизонтальной плоскостью в отдельную часть.

Отчёт анализатора показывается в UI до экспорта (как export gate mathsculpt).

### 4.6 Построение оснастки (mold/)

Общее: изделие масштабируется на (1 + shrinkagePct/100) до построения.

1. **spare.ts** — литейная горловина: усечённый конус-кольцо над венчиком
   (внутр. диаметр ≥ горла, высота spare.heightMm). Для drop-out не нужна
   (льют в открытый верх).
2. **block.ts** — гипсовый блок(и):
   - габарит: bbox изделия + plasterMm со всех сторон, скруглённые рёбра;
   - `block_full = box − (изделие ⊔ spare)`;
   - halves: `splitByPlane(block_full, y=0)` → 2 половины;
     ключи: полусферы на плоскости разъёма — у одной половины −sphere,
     у другой +sphere (позиции детерминированы от габарита);
   - drop-out: блок целиком, полость открыта вверх;
   - +bottom: дополнительный горизонтальный разрез с кольцевым ключом.
3. **master.ts** (режим «мастер-позитив»): изделие ⊔ spare ⊔ опциональный
   фланец по плоскости разъёма (упрощает ручную укладку пластилина) — 1 STL.
4. **bath.ts** (режим «ванночки»): на каждый блок —
   `bath = box(габарит блока + clearMm + wallMm, высота блока + запас)
   − block` , ориентированная рабочей поверхностью вверх, дно плоское для
   печати. Т.е. печатная деталь содержит позитив блока, встроенный в опалубку:
   заливаем силикон → негатив блока → заливаем гипс → рабочая полуформа.
5. Экспорт: ZIP не делаем — несколько STL по очереди с говорящими именами
   (`clayform-pot-half-A.stl`, `-half-B.stl`, `-bath-A.stl`, …).

Каждая деталь проходит validate.ts export gate (+ manifold сам гарантирует
замкнутость — проверяем оба слоя).

## 5. UI

Раскладка mathsculpt (панель слева, канвас справа, граф профиля):

1. **Форма**: 4 семейства (иконки-силуэты), слайдеры параметров семейства,
   высота в мм; live-силуэт r(z) (graph.ts).
2. **Рельеф**: карточки wave / wave² / roulette (механика cards.ts).
3. **Ручка / носик**: чекбоксы + параметры.
4. **Экспорт** — 3 таба:
   - Печать изделия: стенка мм, дно мм → 1 STL (hollow);
   - Мастер-позитив: усадка %, горловина → 1 STL;
   - Ванночки: усадка, гипс мм, ключи, борта → N STL + схема разъёма
     (авто, с отчётом анализатора и предупреждениями о поднутрениях).
5. Превью: изделие — как в mathsculpt; для оснастки — предпросмотр деталей
  разнесённым «взрывом» с подписями (A/B/дно).
6. Undo/redo, пресеты, share-links — механика mathsculpt.

Тяжёлые сборки (CSG, экспорт-резолюция) — в worker'е с прогрессом.

## 6. TDD-процесс и вехи

Правила: тест пишется до кода; каждый модуль geo — юнит-тесты на чистых
функциях; после каждой вехи `npm run check` зелёный; golden-тесты фиксируют
геометрию (обновление только осознанно `UPDATE_GOLDEN=1`); инварианты для
каждого экспортируемого меша: finite, watertight, volume > 0, extents верны.

- **M0. Каркас.** Скопировать инфраструктуру mathsculpt, вычистить лишнее,
  пустое приложение собирается, `check`/`smoke` зелёные.
- **M1. Спайк manifold-3d.** Загрузка WASM в vite + worker, адаптер
  SurfaceMesh⇄Manifold, тест: куб ∪ сфера watertight. Риск снят.
- **M2. Профили семейств.** 4 генератора `params → ProfileDef` + клампы;
  тесты: монотонность зон, диаметры соответствуют параметрам, golden-силуэты.
  UI: выбор семейства, слайдеры, силуэт, превью тела вращения.
- **M3. Рельеф + ролик.** relief.ts, тесты: периодичность, замыкание ролика
  по окружности (N целое), зоны/fade, амплитуда в мм. UI-карточки.
- **M4. Полое изделие (прямая печать).** hollow.ts на базе mathsculpt,
  стенка/дно в мм; тесты watertight + golden. Экспорт STL №1 работает.
- **M5. Ручка и носик.** handle/spout + union; тесты: watertight после union,
  объём > объёма тела, симметрия y→−y (ручка в плоскости разъёма), lip-носик
  не ломает венчик. Полая печать с ручкой.
- **M6. Анализатор разъёма.** analyze.ts; тесты на эталонных случаях: миска →
  drop-out, горшок → halves, ваза с ножкой → halves+bottom, ролик с
  запредельной глубиной → warning.
- **M7. Оснастка.** spare, block, master, bath; тесты: блоки watertight,
  `volume(A)+volume(B) ≈ volume(box − изделие − spare)`, ключи парны
  (папа/мама совпадают по позициям), ванночка = валидный негатив блока
  (union(bath, block) без полостей), усадка масштабирует габарит.
  UI-табы экспорта, «взрыв»-превью, имена файлов.
- **M8. Полировка.** Пресеты по референсам, share-links, undo/redo, smoke/shot,
  README, предупреждения печати (свесы) из mathsculpt.

Порядок фиксированный: M5 (CSG изделия) раньше M6/M7, т.к. анализатор и
оснастка работают с финальным позитивом, включая ручки.

## Итог: чем сделанное отличается от плана

Все вехи M0…M8 пройдены. Расхождения — там, где реальность оказалась
интереснее замысла:

1. **Интерполяция силуэта.** Планировался Эрмит с тангенсами конечных
   разностей, как в mathsculpt. Оказалось, он перелетает контрольные точки на
   5–10 %, и заявленный «диаметр тулова» расходится с фактическим. Добавлен
   ограничитель Фрича–Карлсона: в локальных экстремумах тангенс зануляется,
   поэтому максимум силуэта лежит ровно на контрольной точке.

2. **Стенка полого изделия.** Планировался офсет по нормали — так и сделано,
   но выяснилось, почему это критично: у миски стенка идёт под 30–40° к
   столу, и радиальный сдвиг (как в mathsculpt) дал бы вдвое тоньше
   заданного. Полость строится по гладкому силуэту, без рельефа: изнутри
   посуда гладкая и у гончара, и при литье.

3. **Две половины подходят всегда.** План предполагал, что анализатор
   выбирает между схемами по поднутрениям. Выяснилось: у тела вращения при
   разъёме на две вертикальные половины поднутрений не бывает в принципе
   (нормаль лежит в осевой плоскости). Значит выбор сводится к вопросу «а
   нельзя ли обойтись одной частью», а отдельная донная плита — не
   геометрическая необходимость, а практика для широкого плоского дна.

4. **Угловой рельеф запирает форму.** Не было в плане: волна по спирали или
   вокруг оси пересекает плоскость разъёма под углом, и форму пришлось бы
   вывинчивать. Кольцевые валики она отпускает свободно. Приложение это
   различает и говорит, что менять.

5. **Ванночка — объединение, а не вычитание.** В плане было «bath = box −
   block». Неверно: печатная деталь должна физически СОДЕРЖАТЬ позитив
   блока, иначе силикону не во что затекать.

6. **Узоры накатки.** Вместо `chevron` сделан `lattice` (перекрёстная сетка):
   зигзаг и «ёлочка» выглядели почти одинаково, а сетчатый накат — классика.

7. **Web Worker не понадобился.** Планировался для полной резолюции, но
   узкое место оказалось не в числе граней (192×192 строится за 10 мс), а в
   булевых операциях. Оно решается задержкой пересборки и огрублённой
   сеткой в превью.

8. **Приставного носика нет.** Оттянутый край покрывает и крынку, и кувшин, и
   ойнохойю; трубчатый носик отложен.

## 7. Открытые вопросы (решать по ходу, не блокируют старт)

1. Производительность manifold на экспорт-резолюции (512×512 тело + ручка +
   блоки) — если медленно, снижать резолюцию тел для CSG-этапа оснастки
   (рельеф в гипсовой форме нужен, но 256×256 может хватить). Замерить в M1/M7.
2. Скругление наружных рёбер гипсового блока: minkowski дорог; вариант —
   строить наружный габарит как параметрический скруглённый бокс.
3. Ролик поверх ручки: рельеф применяется только к телу вращения до union —
   зафиксировать в доке поведения.
4. Drop-out форма для чашек с бочкообразностью (barrel > 0 даёт поднутрение
   при вытяжке вверх) → анализатор переключит на halves; проверить UX.
5. Двухчастная силиконовая форма для мастера-позитива (режим «оба») — v1
   печатает только мастер; фланец разъёма — как опция мастера.
